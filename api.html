API do Trajeto (formato trajeto.v1)

Liga a tua aplicação à conta de um motorista no Trajeto: lê e envia clientes e serviços em JSON, nos dois sentidos.

Como funcionaChaveLerEnviarFormatoA tua appErrosLimites

Como funciona

1 · O motorista cria a chaveNo Trajeto: Minhas tarifas → 🔗 Integrações → Criar chave. Cada chave só dá acesso aos dados dessa conta e pode ser apagada a qualquer momento.
2 · A tua app usa a chavePara ler os clientes e serviços e para enviar clientes e serviços novos ou alterados.
3 · O motorista sincronizaNada é automático. Quando o motorista toca em Sincronizar agora, o Trajeto aplica o que enviaste e publica os dados atualizados.
Importante: o que envias fica em fila e entra no Trajeto na próxima sincronização. O que lês é o estado da última sincronização (o campo atualizadoEm diz quando foi).

Endereço base:

https://trajeto-pagamentos.leonardospinasse.workers.dev/v1

Autenticação

Envia a chave em todos os pedidos, num destes cabeçalhos:

Authorization: Bearer trj_live_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
X-Api-Key: trj_live_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

A chave pode ter permissão para ler, para enviar, ou para as duas coisas. Guarda-a no teu servidor, nunca no código de uma página ou app pública.

Ler dados

PedidoO que devolve
GET /v1/contaNome da conta, data da última sincronização, totais e permissões da chave.
GET /v1/clientesTodos os clientes. Filtros: ?desde=2026-11-01 (alterados desde), ?telefone=912345678, ?nome=silva.
GET /v1/clientes/{id}Um cliente (id do Trajeto).
GET /v1/servicosTodos os serviços, com valores e moradas. Filtros: ?desde=, ?de=2026-12-01, ?ate=2026-12-31 (pela data do serviço).
GET /v1/servicos/{id}Um serviço (id do Trajeto).
curl -H "Authorization: Bearer trj_live_…" \
  "https://trajeto-pagamentos.leonardospinasse.workers.dev/v1/servicos?desde=2026-11-20"
{
  "formato": "trajeto.v1",
  "atualizadoEm": 1764151200000,
  "total": 1,
  "servicos": [
    { "id": "m1", "tipo": "transfer", "data": "2026-11-29", "hora": "07:00",
      "cliente": { "nome": "John Smith", "telefone": "+351912345678" },
      "partida": "Hotel Avenida Palace", "chegada": "Aeroporto de Lisboa",
      "valor": 40, "estado": "agendado", "atualizadoEm": 1764151200000 }
  ]
}

desde aceita uma data (2026-11-20), data e hora ISO, ou milissegundos.

Enviar dados

PedidoO que faz
POST /v1/clientesCria um cliente. Se já existir um com o mesmo telefone, o Trajeto atualiza-o em vez de duplicar.
PATCH /v1/clientes/{id}Atualiza um cliente. O {id} pode ser o id do Trajeto ou o id da tua app.
POST /v1/servicosCria um serviço. Se faltarem dados, a resposta diz quais (faltam) e o serviço fica em “Por completar” no Trajeto.
PATCH /v1/servicos/{id}Atualiza um serviço (só os campos que envias). Serviços já concluídos não são alterados.
POST /v1/importarVários de uma vez: {"clientes":[…],"servicos":[…]}, até 500 itens.

Para criar, manda sempre o id do item na tua app. É assim que o Trajeto sabe que é o mesmo item e não duplica.

curl -X POST -H "Authorization: Bearer trj_live_…" -H "Content-Type: application/json" \
  "https://trajeto-pagamentos.leonardospinasse.workers.dev/v1/servicos" \
  -d '{ "id": "PED-1042", "tipo": "transfer", "data": "2026-11-30",
        "cliente": { "nome": "Manuel Silva", "telefone": "+351912000488" },
        "partida": "Aeroporto de Lisboa, T1", "chegada": "Hotel Tivoli" }'

Resposta (202: recebido, fica em fila até o motorista sincronizar):

{ "formato": "trajeto.v1", "recebido": true,
  "resultado": { "eid": "e_…", "id": "PED-1042", "faltam": ["hora", "valor"] } }

Campos desconhecidos são ignorados. Textos longos demais são cortados. Datas e horas em formato errado são ignoradas e contam como “em falta”.

Ligação no outro sentido: o que a tua app tem de ter

Se quiseres que o próprio Trajeto envie e traga dados quando o motorista toca em Sincronizar agora, a tua app precisa de um endereço https. O motorista cola esse endereço e uma chave tua em Integrações → App ligada. O Trajeto chama esse endereço com:

Authorization: Bearer <a chave que deste ao motorista>
X-Trajeto-Formato: trajeto.v1

POST o teu endereço: o Trajeto envia

{ "formato": "trajeto.v1", "enviadoEm": "2026-11-26T11:00:00.000Z",
  "conta": { "nome": "Trajeto Lisboa" },
  "clientes": [ { "id": "cA", "nome": "Ana Costa", "telefone": "+351912345678" } ],
  "servicos": [ { "id": "m1", "tipo": "transfer", "data": "2026-11-29", "hora": "07:00", "valor": 40, "estado": "agendado" } ] }

Responde com 200. Opcionalmente, diz o que recusaste, para o motorista ver:

{ "clientes": { "aceites": 1, "recusados": [] },
  "servicos": { "aceites": 0, "recusados": [ { "id": "m1", "motivo": "data no passado" } ] } }

GET o teu endereço: o Trajeto traz

Recebes ?desde= (data ISO da última vez) na segunda sincronização em diante. Devolve:

{ "clientes": [ { "id": "P1", "nome": "Rui Novo", "telefone": "961111111" } ],
  "servicos": [ { "id": "PED-1042", "data": "2026-11-30", "hora": "16:40",
                  "cliente": { "nome": "Manuel Silva" },
                  "partida": "Aeroporto T1", "chegada": "Hotel Tivoli", "valor": 48.9 } ] }
Quando devolves um item que veio do Trajeto, manda o id do Trajeto em trajetoId (ou no próprio id). Assim não fica duplicado.

O Trajeto espera no máximo 20 segundos pela resposta.

Respostas e erros

CódigoQuando
200Leitura com sucesso.
202Envio recebido, em fila até o motorista sincronizar.
400JSON inválido ou endereço errado (ex.: PATCH sem id).
401Falta a chave, ou a chave é inválida ou foi apagada.
403A chave não tem essa permissão (ler ou enviar).
404Recurso ou item não encontrado.
413Pedido grande demais (mais de 500 itens).
422Item inválido (ex.: criar sem id).
429Há mais de 2000 itens à espera. O motorista tem de sincronizar primeiro.

Os erros vêm sempre como {"erro": "mensagem"}.

Limites e boas práticas

  • Até 5 chaves por conta, 500 itens por pedido e 2000 itens à espera.
  • Para muitos itens, usa /v1/importar em vez de muitos pedidos seguidos.
  • Envia sempre o id da tua app. Reenviar o mesmo item não o duplica.
  • São dados pessoais de clientes: usa só o que precisas e trata-os segundo o RGPD. O motorista é responsável pelos dados que partilha com a chave dele.
